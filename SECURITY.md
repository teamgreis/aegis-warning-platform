# Security Policy

## Supported scope

At this early stage, only the current development branch is expected to receive fixes.

## Reporting

Please do not disclose vulnerabilities, exploit details, credentials, or sensitive operational data in public issues. Contact the repository owner privately until a dedicated security reporting channel is established.

## Expectations

- Include affected component, impact, reproduction conditions, and suggested mitigation.
- Do not test against real public-warning infrastructure or third-party systems without written authorization.
- Do not use real public alert channels for proof of concept.
- Do not include private keys, access tokens, or personal data in reports.

A verified security contact and formal vulnerability handling process must be established before any external operational pilot.
